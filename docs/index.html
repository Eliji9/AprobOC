Condiciones estándar del Flexible Workflow

Se configuran pasos con las condiciones que SAP ya entrega. Si ningún paso aplica, el workflow libera la OC solo. Sin código y sin BAdIs.

Solución

  1. S/4 · Manage Workflows for Purchase OrdersPasos de aprobación con condición estándar de monto neto, por moneda (USD, COP…).
  2. S/4 · Flexible Workflow estándarSi el monto está bajo el umbral, ningún paso aplica y la OC se libera al guardarse.
  3. S/4 · Revisión periódicaAjustar los umbrales en moneda local cuando la tasa de cambio se mueva.

Objetos a crear

Ninguno. Solo configuración en la app estándar, a cargo del administrador del workflow.

Application Job aprobador en S/4

Un job con el usuario genérico busca las tareas pendientes, evalúa la regla en USD y aprueba. Es el reemplazo directo del job de ECC.

Solución

  1. S/4 · Flexible Workflow (sin cambios)La OC entra a aprobación según la configuración actual.
  2. S/4 · Application Job, cada 1–5 minBusca tareas TS00800531 abiertas y calcula el total en USD con la clase de reglas.
  3. S/4 · Wrapper Tier 2Si cumple el rango del nivel, reenvía la tarea al usuario genérico (si no es agente) y la aprueba. Si no cumple, queda para aprobación manual.
  4. S/4 · Application LogRegistra OC, nivel, monto USD y rango aplicado.

SAP Build Process Automation con tabla de decisión

Un proceso programado en BTP lee las tareas pendientes, evalúa una tabla de decisión que mantiene el negocio y aprueba. Sin IA.

Solución

  1. S/4 · Flexible Workflow (sin cambios)La OC entra a aprobación según la configuración actual.
  2. BTP · Proceso programado, cada 5–15 minLee las tareas pendientes con TASKPROCESSING y el total USD con un servicio de S/4.
  3. BTP · Tabla de decisión de BuildEvalúa nivel y monto contra los rangos que define el negocio.
  4. BTP → S/4 · DestinoSi cumple, aprueba con Decision usando el usuario técnico. Ver "Cómo aprueban C y D".

Cómo aprueban C y D

Las dos usan el mismo servicio que My Inbox, llamado desde BTP con un destino y un usuario técnico. En C lo orquesta un proceso con pasos fijos; en D, un agente. El historial de la OC muestra al usuario técnico como aprobador, con el comentario que se envíe.

1 · GETTaskCollectionTareas READY de TS00800531
2 · GETDecisionOptionsClave de la decisión "Aprobar"
3 · POSTDecisionAprueba con comentario (requiere token CSRF)
Punto crítico TASKPROCESSING es el inbox del usuario conectado: solo devuelve las tareas donde ese usuario es agente. Un usuario administrador no ve las tareas de otros por esta vía, y la configuración del workflow está congelada, así que no se puede agregar como aprobador.

Recomendación

Salir con la opción B y dejar la A como destino cuando se libere la configuración del workflow. B es la única que hoy no toca el workflow, mantiene la regla exacta en USD y no tiene costo adicional. La tabla y la clase de reglas sirven además como referencia para definir los umbrales de la A.
